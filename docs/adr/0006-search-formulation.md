# ADR 0006：搜索形式化：UCT-rollout 与 NN 引导搜索

- 状态：已采纳
- 日期：2026-10-06

## 背景

冷启动阶段还没有网络，需要一条“不依赖神经网络也能产出价值数据”的搜索；
有了网络之后，又需要一条用双头网络引导的搜索。两者必须共用同一套价值语义
（ADR 0004 定义的 `A(u)` / `Q(s,a)` / `V(s)`），否则数据与模型之间会悄悄错位。

## 决策

### 共同部分：树结构

决策节点（轮到玩家）与随机块节点（afterstate，等一个随机块）交替：

* **决策节点**：边 = 合法方向；每条边的 afterstate 与立即得分在节点创建时算好。
* **随机块节点**：没有“选择”可言，按真实规则采样一个生成结果（空格与 2/4），
  把该结果按 `(空格, 是否 4)` 缓存为 lazy 子节点；同一个结果再次被采样到时复用子树。

回传时穿过“随机块节点 → 决策父节点”这条边会把该边的立即合并得分计入返回值，
于是父节点的 Q 自然等于 `r(s,a) + A(u)`——不需要任何修正项。

### UCT + 随机 rollout（无网络，冷启动用）

* 决策节点用 UCT 选择，Q 在**节点内归一化**（分数跨度从几十到几万，不归一化探索项会失效）。
* 未访问过的合法边一律优先，保证每条边至少被评估一次。
* 新展开的决策节点用均匀随机合法动作 rollout 到终局，返回值即 `V(s)` 的一次采样。
* rollout 内的随机块用 rollout 自己的随机流，与真实环境流分开：调整 rollout 策略不会
  连带改变对局的随机序列。

### NN 引导搜索（PUCT，用网络时）

* 叶子求值：决策节点需要“策略头对决策局面的先验”+“价值头对全部合法 afterstate 的 `A(u)`”；
  随机块节点只需要价值头对 afterstate 的 `A(u)`。
* 选择：`PUCT = 归一化Q + c_puct · P(a) · √N / (1 + n_a)`，其中未访问边的 Q 取
  该边的一次性估计 `r(s,a) + A(u_a)`（AlphaZero/KataGo 的惯例），而不是像 UCT 那样强制
  轮询式访问——有了先验之后，“按先验走”比“每条边轮流一次”更合理。
* 叶子备份值：决策节点取 `max_a (r_a + A(u_a))`，随机块节点取 `A(u)`。
* 动作选择：前 `temperature_moves` 步按根访问分布采样（自对弈需要多样性），
  之后取访问数最大的方向（并列取编号更小者，保证可复现）。
* 每步的树用完即弃（不跨步复用），因此内存只与 `模拟次数 × lane 数` 有关。

### 随机流

所有随机流由 `(基础种子, 用途, 局号, 步号, 序号)` 派生（`game/seeds.h`），
而不是从一条全局流里顺序取。因此 lane 数量、执行顺序都不影响任何一局的结果，
任意一局任意一步都能单独重放——这是 `verify` 能对整批数据做重放校验的前提。

## 理由

* 采样式随机块节点（而不是枚举 16 空格 × 2 数值 = 32 个结果）把每次模拟的节点增长
  限制在 ≤2 个；枚举式展开在 64 次模拟下会炸出上千个节点，而价值由网络给出的
  afterstate 评估本来就已经把随机性期望掉了。
* 让两种搜索共用树结构与价值语义，意味着 NN 搜索不需要第二套“Q 该怎么算”的约定；
  从 UCT 数据训出来的价值头可以直接接到 PUCT 上。
* 节点内归一化与 PUCT 的先验项，都是从旧版（ADR 0002/0020 那批实验）与 KataGo 已经
  验证过的形态，不重新发明。

## 替代方案

* **枚举随机块节点**：精确但节点数爆炸，64 次模拟下无法覆盖，收益不抵成本。
* **纯 one-ply 贪心（不做树搜索）**：旧版实验证明 `argmax_a [r + A(u)]` 可用，但明显弱于
  同模拟预算的搜索；它作为网络策略的基线保留在评测口径里，不作为搜索实现。
* **不做 chance 层、只用 afterstate 值的浅搜索**：实现最简单，但放弃了随机的期望结构，
  与 `A(u)` 的定义（对生成块的期望）不再一致。
* **并行 lane 推进的树**：实测证明瓶颈不在这里（见 ADR 0003），不值得引入并发复杂度。

## 验证方式

* `r2048_tests search`：同参数搜索结果可复现、动作合法、根访问数之和等于模拟次数、
  换种子/换步号结果不同、单次模拟也返回合法动作、有合并的方向拿到更多访问。
* `r2048_tests engine`：批推理引擎在有限轮次内产出恰好 `samples` 条数据；
  相同配置两次运行分片哈希相同。
* 端到端（实测记录见 `docs/BUILD.md`）：随机策略 200 局均分 1200；
  纯 C++ UCT-rollout 64 次模拟 200 局均分 15169（43/200 达到 2048）。
