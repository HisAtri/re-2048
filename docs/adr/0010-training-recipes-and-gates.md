# ADR 0010：训练配方与门槛

- 状态：已采纳
- 日期：2026-10-06

## 背景

训练阶段最容易出的问题不是“训不出来”，而是**用一个看起来在变好的指标掩盖真实的退化**。
旧版留下的两条硬结论直接决定本项目的默认配方：

* 共享主干联合优化会把 value MAE 从约 352 恶化到 13,406 分，进而让 NN-MCTS 弱于纯 MCTS
  （旧版 ADR 0008）→ 策略头默认在**冻结价值**上训练。
* 同数据同配方的架构对照里，双塔（浅层共享 3 块 + 每塔 3 块）以 +5,367 分
  （95% CI [+3,560, +7,186]，247 胜 3 平 150 负）胜出共享主干（旧版 ADR 0011）→
  联合训练默认用双塔。

## 决策

1. **四种配方，一个循环**（`python/src/r2048/nn/training.py`）：
   | 模式 | 前向行 | 损失 | 用途 |
   |---|---|---|---|
   | `value` | afterstate | Huber(MSE 可选) | 冷启动价值头 |
   | `policy` | 决策局面 | 软标签 CE | 在**冻结价值**上训策略头（默认路线） |
   | `joint` | 决策 + afterstate | CE + Huber | 对照臂（共享主干） |
   | `dual` | 决策 + afterstate | CE + Huber | 对照臂（双塔，联合训练里被验证的一臂） |
2. **冻结是默认**：`policy` 模式要求 `--freeze-value` + 源 checkpoint，且冻结逻辑与结构解耦
   （冻结除 `policy*` 之外的全部参数）。冻结随机初始化的价值没有意义，因此缺源 checkpoint 直接报错。
3. **一次前向覆盖两种行**：joint/dual 把决策局面与 afterstate 拼成一个批次，
   价值头取后半、策略头取前半——与自对弈里的批处理协议同一个思路。
4. **D4 增强按样本独立**，但策略样本的棋盘、合法掩码、访问分布必须用**同一个**变换
   （见 ADR 0009 的测试；`augment_joint` 对决策局面与 afterstate 也用同一个变换，
   否则价值标签会落到另一个局面上）。
5. **验证集绝不增强**：增强后指标度量的分布与业务分布不同，既噪声大又不可比。
6. **每个 checkpoint 记录来源**：模型结构（含结构参数）、训练模式、是否冻结价值、
   规则版本、数据批 id 与引擎构建身份、配置哈希、源 checkpoint 哈希、离线指标。
7. **门槛分两类**：
   * **离线指标**（value MAE、policy CE、与搜索实际选招的一致率）只用于**挑 checkpoint 与排查**；
   * **验收**是同 seed 配对对局（ADR 0011 的口径）。旧版的架构对照里两种结构的离线指标几乎
     完全重合（MAE 65.5 vs 63.9、CE 1.2280 vs 1.2276），差别只在同 seed 对局里显现——
     拿离线指标当验收会得出“两者一样”的错误结论。

## 理由

* 冻结价值训练不是保守，而是被实测逼出来的：联合优化保留了一部分动作分类能力，
  却破坏了搜索依赖的叶值尺度，而搜索会把价值质量的微小差别放大成整局分差。
* 双塔的代价在我们实际的批次规模下很小（旧版实测 batch 128 时慢 1.07–1.14×；
  1.5× 只在 batch 1 出现），而收益是 +5,367 分。
* 记录来源信息是为了让“这个 checkpoint 是怎么来的”可回答：数据批、构建身份、
  配置哈希、源模型哈希都在 checkpoint 与 `train.json` 里各写一份。

## 当前实测状态（第一轮，小规模）

| 阶段 | 配方 | 结果 | 判定 |
|---|---|---|---|
| 价值头 | 100 万条随机策略数据，8 轮，batch 8192 | nn_value 均分 3117 vs 随机 1200 | **+1916.9，95% CI [+1706, +2134]，180 胜 20 负 → 通过** |
| 策略头 | 19 万条 MCTS-64 数据，冻结价值，15 轮 | nn_policy 均分 1413 vs 随机 1200 | +212.7，95% CI [+75.6, +356.8] → 显著但很弱 |
| NN-MCTS | 上述模型 + 64 次模拟 | 100 局均分 13698 vs 纯 MCTS-64 15510.6 | −1812.8，95% CI [−3688, +83] → **不显著，未超过纯搜索** |

最后一行与旧版同一阶段的记录一致（他们早期 value + 均匀先验对纯 MCTS 是 +722、
95% CI [−1302, +2732]，同样不显著）。差距的来源是明确的，都属于“训练计划”而不是“基础管线”：

* **教师太弱**：当前的策略教师是“64 次模拟 + 随机 rollout”的 UCT，其根访问分布噪声很大；
  旧版后来改用 NN 引导的搜索并加上候选级监督才拿到 +19,103 的配对优势（旧版 ADR 0010）。
* **数据太少 + 步数太少**：策略头只训了 703 步（19 万条 × 15 轮 / 4096），
  旧版的对照组是 2000 万级样本、数千步。
* **价值头只做了一轮 MC 拟合**：没有 TD(0) 自举细化，也没有用更好的行为策略重新生成数据。

## 替代方案

* **默认联合训练（共享主干）**：实现最简，但旧版实测把价值表示训坏，是已知会退化的路线。
* **冻结价值 + 只训策略头 → 直接作为最终模型**：当前就是这样，但它依赖教师质量；
  教师弱时策略头只能学到教师噪声的上界。
* **端到端从对局回报直接训策略头（REINFORCE/PPO 类）**：与旧版验证过的“模仿搜索分布”路线不同，
  在没有价值基线的当前阶段方差会极大；不优先尝试。

## 验证方式

* `python/tests/test_data_and_training.py`：价值模式一轮训练后损失有限、checkpoint 元数据齐全
  （结构、规则版本、数据批、编码、分数尺度）；策略模式缺源 checkpoint 必须报错。
* 端到端手动流程（数字见上表，命令见 docs/BUILD.md）。
* 明确未验证的部分：双塔相对共享主干在本项目数据上的优势尚未复测（旧版结论作为先验）；
  `joint` 模式尚未跑过对照。
