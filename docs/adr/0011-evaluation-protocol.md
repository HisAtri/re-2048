# ADR 0011：评测口径与比较方法

- 状态：已采纳
- 日期：2026-10-06

## 背景

本项目最容易出错的地方不是训不出来，而是**用错误的比较得出结论**。旧版留下的教训很具体：

* 离线指标（value MAE、策略 CE、同根候选排序）在两种结构之间几乎完全重合，
  而同 seed 对局却差 +5,367 分——只看离线指标会误判为“没有差别”。
* 两个模型各自对基线的置信区间重叠，不能推出“两个模型没有差别”；必须做模型间配对检验。

## 决策

1. **三条 track，永不互相解释为同一策略的成绩**（`python -m r2048 eval --track ...`）：
   | track | 决策方式 | 需要什么 |
   |---|---|---|
   | `nn_value` | 单次前向，`argmax_a [r(s,a) + A(u_a)]` | 价值头 |
   | `nn_policy` | 单次前向，`argmax_a π(a\|s)` | **训练过策略头**的 checkpoint |
   | `nn_mcts` | 网络引导的搜索（64 次模拟） | 价值头 + 先验 |
   三条 track 共用 C++ 引擎的**同一套规则与对局推进**，只在“选招”这一处分岔
   （`EngineConfig.decision_mode`），因此成绩之间的差别只来自决策方式本身。
2. **纯网络 track 由元数据闸门把守**：checkpoint 的 `training_target` 不是
   `policy/joint/dual` 时，跑 `nn_policy` 直接报错——否则拿随机先验的成绩当“策略头成绩”。
3. **同 seed 对齐开局**：局号 → 开局的映射由 C++ 的种子派生决定，与 C++ 侧
   `r2048 evaluate` 完全一致。因此任意两个 track 的成绩**按局配对**。
4. **比较用配对 bootstrap**（`python -m r2048 compare`）：对逐局差重采样，
   报均值差、95% 区间、胜/平/负数；区间跨零就明确说“不可下结论”，不给模糊结论。
5. **评测不做采样**：`temperature = 0`，确定性选招；训练跑谱才用温度采样造多样性。
6. **纯 C++ 的 random / MCTS-rollout 基线用 C++ CLI 跑**（`r2048 evaluate`），
   它们不需要网络，也保证“时间只花在 C++ 上”这条基线是干净的。
7. **逐局记录落盘**（JSONL，含 track、模型、模拟次数、seed、分数、最大块、步数）：
   比较与复现都基于这些文件，而不是汇总数字。

## 理由

* 把选招口径集中到引擎的 `decision_mode`，而不是在 Python 里再实现一遍纯网络贪心，
  是为了避免“评测用的对局推进逻辑与跑谱不同”这种最难查的偏差（规则实现只有一份，见 ADR 0004）。
* 手动配对 bootstrap 而不是看两个独立区间：区间重叠量与配对差是两个不同的统计量，
  后者才是“同一批开局上谁更强”的答案。
* 评测 seed 与局数写进逐局记录：换 seed 就得重新配对，缺少 seed 的记录无法参与比较。

## 替代方案

* **固定评测集**（预先抽一批开局存盘）：可复现性更好，但会带来选择偏差——反复在同一批
  开局上调参等于对评测集过拟合。当前做法是同 seed 现场生成开局，靠配对比较控制方差。
* **只看汇总统计量**：无法做配对检验，也无法事后重新比较（例如新增一条 track）。
* **用离线指标挑模型**：已被旧版实测否定（见背景）。

## 验证方式

* `python/tests/test_data_and_training.py` 覆盖配对比较的算术（同 seed 对齐、差值、胜负计数）。
* 第一轮实测（seed 20262052，200 局，同一批开局）：
  | 对照 | 均值差 | 95% CI | 胜负 |
  |---|---|---|---|
  | nn_value − random | **+1916.9** | [+1706.3, +2133.9] | 180 胜 0 平 20 负 |
  | nn_policy − random | +212.7 | [+75.6, +356.8] | 109 胜 0 平 91 负 |
  | NN-MCTS64 − 纯 MCTS64（100 局） | −1812.8 | [−3688.5, +83.4] | 43 胜 1 平 56 负 |
  第三条区间跨零，结论只能是“尚未超过纯搜索”，不能写成“更差”或“相当”。
* 吞吐：纯网络 track 约 57–97 局/秒（单次前向），NN-MCTS-64 约 2.5 局/秒（每局约 808 步）。
