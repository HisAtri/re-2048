# ADR 0012：评分标度、配对诊断与两轮迭代实验

- 状态：已采纳
- 日期：2026-10-06

## 背景

要回答“模型能力差异有多大”，必须先回答两个更基础的问题：**用什么标度衡量一局**、
**用什么比较两个模型**。

* 单局得分是重尾分布：少数高分局能主导均值，直接比均分会让结论随一两局摆动。
* 同 seed 评测只对齐**开局**。2048 的开局在棋盘层面只有 **480 种**（16 选 2 个格子 ×
  4 种数值组合），按 4×4 的 D4 对称群简并后只剩 **75 种**（这两个数字由
  `python -m r2048 rating` 直接算出来，不是估计）。第一步之后每次随机块生成都会改变后续轨迹，
  状态空间随即不可数——所以“同 seed”提供的配对信息在几十步之内就被耗尽了。

## 决策

1. **按局取 `log2(score + 1)` 再算均值**（沿用旧版 `src/ai2048/rating.py`）：
   230 分 = 一倍分数，尾部不再主导。展示层同时给出原始均分与中位数，但不作为比较口径。
2. **评分 = 1000 + 230 × (模型对数均值 − 锚点对数均值)**，锚点按评分线固定：
   * `pure` 线（单次前向、无搜索）：锚点 = 随机策略；
   * `search` 线（同一次模拟预算下的搜索）：锚点 = 纯 MCTS-rollout 64 次模拟。
   没有锚点的线不产出评分——宁可缺，也不要给一个没有尺度的数字。
3. **区间用两样本独立公式**（不是配对公式），因为配对没有方差缩减作用（见下）。
4. **配对诊断作为常备工具**（`rating --pair-a X --pair-b Y --pair-track T`）：
   报逐局 log2 得分的相关系数与“配对把标准误压低了百分之几”，用数字回答
   “同 seed 到底有没有用”，而不是默认它有用。
5. **评分线按 (track, 协议哈希) 分组**，协议哈希包含规则版本与模拟预算：
   同一模型在 64 次与 128 次模拟下的成绩不可比，因此落在不同线上。
   C++ 评测写出的记录没有 track 字段，按 `policy ∈ {random, mcts}` 推断，
   避免把纯 MCTS 误归到纯网络那条线（那会让搜索线少掉基准锚点）。
   协议的完整清单与两处修正见 [ADR 0016](0016-protocol-variables-and-simulation-budget.md)：
   NN 路径还要把 `c_puct` 与批组成（`lanes/in_flight/max_batch`）算进协议，
   而**评测 seed 不该算进协议**（它只是同一协议下的重复抽样，现在被写进了哈希，
   导致同一模型在两个 seed 上永不合并，与第 6 条的池化目的冲突；修正待实施）。
6. **池是 append-only**，按 `(模型, 线, 协议, 评测种子, 局号)` 去重：
   重复 ingest 是常规操作（新增对局后全盘重算），不去重会把同一局算两次、人为压低区间。
7. **不同样本量用“每万局到达率”**而不是绝对次数：分母不同是最常见的误读来源。
8. **迭代实验口径**：每轮数据集 100 万条，评测统一 400 局、记录 seed；
   轮与轮之间只改数据来源（第 1 轮纯 MCTS-64 教师，第 2 轮用第 1 轮模型跑 NN-MCTS），
   配方不变（价值头 + 冻结价值的策略头），这样评分的差异归因于数据而不是超参。

## 理由

* 用对数标度 + 锚点，是为了让“+230 分”这种说法有稳定含义（分数翻倍），
  而不是让“+1000 均分”随分布的尾部抖动。
* 把配对诊断做成工具而不是原则：**配对是否有效是一个可测量的事实**。
  实测（本轮 search 线，nn_mcts 对纯 MCTS-64，100 个共同局号）：

  | 口径 | 评分差 | 95% CI | 标准误 |
  |---|---|---:|---:|
  | 独立两样本（评分口径） | −20.8 | [−66.1, +24.5] | 0.1005 log2 |
  | 同 seed 配对差分 | −20.8 | [−66.3, +24.7] | 0.1010 log2 |

  逐局 log2 得分相关系数 **−0.011**，配对把标准误压低了 **−1.0%**（即完全没有作用）。
  这与旧版 `rating.py` 自己的记录一致（“开局对单局 log2 得分的方差分量估计为 0”）：
  开局只差两个块的位置与数值，被后续几百步的随机生成完全淹没。
  结论：**同 seed 的价值在于让评测可复现与可追溯，不在于压缩区间**；
  要压区间只能加局数（区间随 1/√n 收缩）。
* 按 (线, 协议) 分组而不是把所有成绩混在一起：64 次与 128 次模拟、有无搜索，
  这些都不是同一个实验条件，混在一起算出来的“评分”没有意义。

## 替代方案

* **固定评测集**（预先抽一批开局存盘）：可复现性更好，但反复在同一批开局上调参会带来
  选择偏差；且既然开局方差分量近 0，固定开局也换不来区间缩小。
* **把配对差作为主口径**（旧版架构对照用过）：在这类轨迹完全分岔的博弈上，
  配对与独立口径给出的标准误几乎相同（上表），因此没有理由把配对当成更精确的估计。
* **用原始均分排名**：尾部主导，且不同样本量不可比。
* **跨协议合并评分**（例如把 64 与 128 次模拟放在一条线上）：会让“评分”同时包含
  方法与预算两个变化，无法归因。

## 验证方式

* `python -m r2048 rating` 在池上重算评分并打印配对诊断；`--json` 落盘完整结果。
* 开局计数由 `count_openings()` 现场计算（480 / 75），不是引用文献。
* 两轮迭代实验的量化结果见下表（评测 seed 20262053，400 局；评分基准见各线的锚点）。

### 第一次实验：价值头只用 MCTS-64 数据训练（复现旧版的已知失败）

| 线 | 模型 | 评分 | 均分 | 每万局到 4096 |
|---|---|---:|---:|---:|
| pure | it2-value | 1152.5 | 2004 | 0 |
| pure | it1-policy | 1080.4 | 1494 | 0 |
| pure | it2-policy | 1011.7 | 1266 | 0 |
| pure | random（锚点） | 1000.0 | 1146 | 0 |
| pure | **it1-value** | **858.1** | **757** | 0 |
| search | it2-nnmcts64 | 1008.4 | 16334 | 75 |
| search | mcts（锚点） | 1000.0 | 15160 | 0 |
| search | **it1-nnmcts64** | **522.0** | **3779** | 0 |

价值头在 MCTS-64 数据上训练后**低于随机策略**（858 < 1000，均分 757 < 1146），
于是它的 NN-MCTS 只有纯搜索的一半评分（522）。这与旧版 ADR 0003 记录的现象一致：
MCTS 量级的标签训出的价值头在**贪心决策**上退化（他们当时是网络贪心 801 vs 随机 1148）。
旧版的解法是改用随机策略数据训练价值头（ADR 0004），或后来加入候选级监督（ADR 0010）。
