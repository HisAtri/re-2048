# ADR 0026：模型命名分层与版本层级（测试版 / 正式版）

- 状态：已采纳
- 日期：2026-10-07

## 背景

ADR 0024 把模型定义拆成了一版一模块，并把 `VERSION_ID` 定性为"索引"。但它的**论证写错了一处**，
本 ADR 先订正那一处，再定下名字本身该怎么起——因为原来的名字（`dual_tower_v1`）读不出体量。

错在哪（逐条）：

1. **"把结构写进 ID 会逼着 ID 随任何宽度调整改名，所以各处都要跟着动"——这个前提是错的**。
   换宽度本来就是一个新模型、就该有新名字：改名不是代价，而是正确行为。真正该守的界线只有
   一条：**名字不参与结构推导**（否则名字写错就静默建成另一个网络），而不是"名字不该有信息量"。
   我把这两件事写成了同一件。
2. **"旧版那种 `s3p3v3-c64` 只能靠 ID 反推结构"——这句对旧版描述错了**。旧版是从 metadata
   *算出*代号（`identity.arch_code`），它的毛病是 `create_model()` 忽略 `shared_blocks` /
   `tower_blocks`、永远按 3/3 建网（写在它自己的注释里），与"读 ID 反推"无关。
3. 结论：`dual_tower_v1` 这种"族名 + 版本号"的写法既没让人读出体量，又容易让人忽略
   "名字与结构之间是有固定关系的"——本该一眼看出 `64 通道 / 3+3+3 块`，却只看到一族名字。

## 决策

1. **名字分成两层，都只是朴素字符串**：

   * **测试版 ID**：创建日期 + 流水号（`20261006001`），只用于架构可行性研判期的产物；
   * **正式版别名**：转正后给一个形状代号（`dt-s3p3v3c64` = 共享 3 块 + 策略塔 3 块 +
     价值塔 3 块 + 64 通道；`sh-s6c64` = 全共享 6 块 + 64 通道），面向用户，
     提供体量参考。转正后**正式别名优先**用于索引、metadata 与产物/仓库命名。

2. **同一份定义可以有多个名字**（`VERSION_ID` = 正式别名，`ALIASES` = 历史名字）。
   旧产物记着旧名字、改不了也不该改，所以旧名字必须继续解析；但**新产物只写 canonical**。
   别名只影响"按名字找定义"这一处查表。

3. **硬线：名字不参与任何计算或结构推导。** 唯一的用途是
   `REGISTRY[canonical_id(name)]` 这一次查表（以及给人看）。不写形状代号解析器、
   不按前缀分派、不从名字推通道数——结构只来自 `architecture_params`。
   测试用"语法完全正确但不存在的代号（`dt-s9p9v9c999`）必须被拒绝"来钉住这条。

4. **发布文件名语法**（正式产物的展示名）：

   ```
   <正式别名>-<发布日期+流水号>-s<训练样本数>.pt
   例：dt-s3p3v3c64-20261007001-s1000000.pt
   ```

   三段各自是"什么结构 / 哪一次发布 / 用了多少数据"。**文件名只作展示**：加载靠的是文件里的
   metadata，改文件名不影响任何事（这与 ADR 0020 的"清单才是提交日志"同一原则）。
   量化对齐版本在文件名上加自己的后缀（如 `-q8a128`），并在 metadata 的 `weights_dtype`
   里写清自己的精度。

5. **`weights_dtype` 现在就记**（值恒为 `float32`），并且加载侧**认得出别的值就拒绝**。
   这是"量化对齐版本"这条支线唯一需要现在就插的桩：`load_state_dict` 会把量化权重静默转成
   float32，事后无法从文件里判断"这份权重被降过精度"，所以记录必须在降精度**之前**就存在
   （订正 ADR 0025 决策 4 的"不预留 metadata 字段"：字段现在记，转换工具与量化加载路径仍然不做）。

6. **两个既有定义按此分层改写**（它们的旧名字进别名表，20 个已有产物继续可加载）：

   | 正式别名（canonical） | 历史名字（`ALIASES`） | 形状 |
   |---|---|---|
   | `sh-s6c64` | `dual_head_resnet_v1` | 6 共享块 + 64 通道 |
   | `dt-s3p3v3c64` | `dual_tower_v1`、`20261006001`（测试版号） | 共享 3 + 策略塔 3 + 价值塔 3 + 64 通道 |

   `sh-s6c64` 没有测试版号（它在分层命名之前就存在），不编造。

## 理由

* **为什么正式别名要比测试版号优先用于索引**：读者在评分表、仓库名、文件名上需要的
  是"这是什么网络"，而不是"它哪天建的"。日期号的价值只在研判期——那时一份定义随时可能被
  丢掉，唯一有意义的信息就是"哪一批实验、哪个时间点"。
* **为什么旧名字不能删**：20 个 checkpoint 的 metadata 记着 `dual_*_v1`，评分池里也有以它们
  产出的模型为对象的记录。删掉别名等于让这些产物变成"不认识的模型"，而它们正是历史对照的基线。
* **为什么文件里的 metadata 才是权威**：文件名会被人重命名、会被流水线拼接、会在复制时丢掉
  后缀；metadata 跟着权重走。把"这份权重是什么"压在文件名上，等于让搬运决定语义。
* **为什么 `weights_dtype` 要在降精度之前就存在**：它是唯一能在事后回答"这份权重是否与原件
  等价"的凭据；一旦有了量化产物再补，已有产物仍然缺这个键，那条支线就永远带着一段"可能被
  当成原件"的历史。

## 替代方案

* **保持 `dual_tower_v1` 这种族名 + 版本号**：就是被订正的那一版，读不出体量。
* **只用形状代号、不要测试版号**：研判期的产物会带上一堆一天后就作废的正式名字，
  评分表与目录里会积累大量"长得像正式版"的东西。
* **把形状代号做成可解析的规格（代码按它构造网络）**：这正是要避免的——名字写错就静默建成
  另一个网络，而"名字错了"是最容易发生、最难发现的一类错误。
* **用文件名当权威标识（不用 metadata）**：见理由。
* **rm -rf 旧名字、把 20 个产物重命名/重写 metadata**：历史产物是基线与对照，不该为了命名
  好看去改动；别名表零成本地解决这个问题。

## 验证方式

* **`python/tests/test_model_registry.py`**（9 条）：
  * `test_names_are_only_lookup_keys`：语法正确但未登记的代号（`dt-s9p9v9c999`）被拒绝
    （钉住"名字不参与结构推导"）；所有别名与 canonical 指向同一个类；测试版号
    `20261006001` 可解析；新产物 metadata 写的是 canonical。
  * `test_weights_dtype_is_recorded_and_other_values_refused`：metadata 记 `float32`；
    写成 `int8-g128` 的 checkpoint 被**指名拒绝**；没有这个键的历史文件按 `float32` 加载。
  * `test_architecture_conflict_is_precise`：同一份定义的两个名字（旧名 vs 正式别名）
    不算"改了结构"——这是改名之后最容易误报的一处，已按 canonical 比较修掉。
* **向后兼容（实测）**：`$R2048_OUTPUT_DIR/runs/*/model.pt` 的 **20 个既有 checkpoint
  在改名后仍然全部 strict 加载通过**（它们的 metadata 记着 `dual_head_resnet_v1`，
  经别名表解析到 `sh-s6c64`）。
* **尚未验证 / 待办**：
  1. 发布文件名语法与模型 ID 的生成**还没有实现**（发布层整体是待做项，见 ADR 0024 的结论）：
     本 ADR 只把它定下来，等导出步骤落地时按此实现，并让 `model_id` 与文件名同源；
  2. 量化对齐版本的加载路径与固定棋盘数值校验未做（ADR 0025 的触发条件未到）；
  3. 测试版号到正式别名的"转正"目前是手工改名（`VERSION_ID` + `ALIASES` 各改一处），
     没有工具支撑；等真的需要频繁转正时再说。
