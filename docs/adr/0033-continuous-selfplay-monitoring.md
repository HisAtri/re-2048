# ADR 0033：连续自举五轮的监控结果——没有劣化、仍未收敛，且进步全在价值头而不在策略头

- 状态：已采纳（监控口径 + 结果）
- 日期：2026-10-08

## 背景

ADR 0030 修好退化后只走了三轮（r1–r3，见其 §6.4）。要继续加轮次，先得回答两个问题：
**有没有劣化**、**能力收敛在什么水平**。这两个问题的难点都在判据上：

* 只看逐轮按局配对差是不够的：自举是闭环，整条线可以一起变差而逐轮差全为零；
* 只看离线指标（策略 CE、候选 MAE）是反向指标（ADR 0030 §3/§5.6 已两条独立证据）；
* 只看下游分数而不看标签，会漏掉最早的预警信号（旧线的同根 std 55.5 → 17.2 → 16.5
  在评测明显变差之前就已经塌缩）。

## 决策

1. **监控口径定为三门尺，缺一不可**，实现落在 `scripts/iterate_monitor.py`：
   * **标签诊断**（`scripts/advantage_probe.py`）：同根 Â std 中位、自洽度、Q̄ 均值、π̂ 熵。
     最早的预警。其中**同根 std 与 Q̄ 的绝对水平有判别力，自洽度没有**（见下"订正"）。
   * **四臂评测**：纯价值 / 纯策略 / NN-MCTS-64 / NN-MCTS-256。搜索臂是真判据；
     纯价值臂是分辨率高 3.5 倍的先行指标（±270 对 ±1,000，ADR 0030 §6.3）。
   * **固定外部锚点**：同预算的纯 rollout MCTS-256（均分 22,600，400 局、同 seed）。
     它是唯一不随自举改变的尺子——"绝对水平在涨"只能由**相对固定锚点的优势**证明。
2. **"不劣化"的判据**（达到即继续加轮，无需人工判断）：
   * 价值臂的每次转移显著为正（它是四条臂里分辨率最高的）；
   * NN-MCTS-256 相对固定锚点的优势不减（允许 ±1,000 的抖动）；
   * 标签同根 std 不塌缩到旧线的量级（<50）；
   * nn256 的步数与到 4096 率不下降。
3. **本轮结果：到 r6 未出现劣化，且尚未收敛，因此继续加轮是安全的。**

## 三条关键观测

**1. 没有劣化。** 五条独立证据一致：价值臂每次转移显著为正；NN-MCTS-256 从 27,419 涨到
40,175（+47%）；相对固定锚点的优势从 121.3% 涨到 177.8%；步数 1423 → 1959；到 4096 率
10% → 36%。ADR 0030 §6.4 里旧线"第二次转移 −1,511（显著退化）"的那一幕没有复现，
标签同根 std 也没有进入旧线那种塌缩（95.6 对旧线的 16.5）。

**2. 仍未收敛——r6 的水平是平台期的下界，不是平台期。** 逐轮增量没有衰减趋势：
nn256 的增量是 +712 / +3,051 / +3,798 / +913 / +4,283，价值臂稳定在 +1,000 ~ +1,500/轮。
标签侧的三个量确实在**饱和**（同根 std 195→96，前三次转移每轮 −24~−29、后两次 −8~−10；
Q̄ 899→1490，增量 +365/+90/+53/+46/+37）——但饱和的是**标签**，不是能力：Q̄ 停在 ~1500
而 nn256 还在涨，说明每轮新数据里的同根排序质量仍在提高（这正是 ADR 0030 §6.4 说的
"标签区分度与学生强度同向而非同一量"）。

**3. 进步全在价值头，不在策略头。** 策略臂 3,258 → 3,477，**五次转移没有一次显著**；
NN-MCTS-64 平在 12.6k~13.2k（且从 r4 起 ≈ 纯价值臂本身，即 64 模拟下的搜索相对纯价值贪心
不再有增益）；而价值臂与 NN-MCTS-256 单调上升。也就是说：**变强来自价值头的同根排序质量，
不来自策略头**。这与 ADR 0032 的策略侧负结果同向——把策略目标换成"更会模仿搜索"（纯蒸馏）
或"更会改进搜索"（Â 加权）都没有动过策略头，推动搜索强度的始终是价值头。

## 订正 ADR 0030 的一条诊断口径

ADR 0030 §6.4 的判据 2 是"机制指标不再塌缩"，其中把自洽度（`argmax(访问数) == argmax(标签)`）
当成塌缩指标。本轮的数据否掉了这条：新线的自洽度从 0.872 掉到 0.581 后**稳定在那里**，
而旧线（确实退化的那条）的自洽度是 0.578/0.583 —— **这一项无法区分健康与退化**，
因为它的下降反映的是"教师从纯 rollout 换成了 NN 自举"（ADR 0030 §3 的表格里 dt2/dt3 也是
0.578/0.583），不是塌缩。有判别力的是**同根 std 与 Q̄ 的绝对水平**（新线 96~195 对旧线 16~17；
新线 Q̄ 899~1490 对旧线 ~425）。后续看板只看同根 std。

## 理由

* **固定外部锚点这条尺子是本轮最重要的方法收获**：自举是闭环，逐轮配对差在"整条线一起退化"
  时会给出一片"不显著"，而"相对同预算纯 rollout" 单调扩大才真正排除了这条退化路径。
  这与 ADR 0032 里"用同一个 Q 度量改进是恒真的"是同一类错误的两面：**度量必须有一个不随被
  测对象移动的参照**。
* **继续加轮的判据必须能自动判定**（价值臂显著为正 + 相对锚点优势不减），否则"要不要再来一轮"
  会退化成看曲线的心情。
* 三轮（ADR 0030）不足以区分"收敛"与"还没发力"：本轮 r4→r5 的 +913（不显著）看起来像平台期，
  r5→r6 立刻给出 +4,283（显著）。这就是为什么判据不能建立在单次转移的显著性上。

## 替代方案

* **只报 nn256 的逐轮差**：会在两轮一起退化时给出"无显著变化"，且 400 局的分辨率（±1,000~2,400）
  让多数单次转移不可判定。本轮能给出结论靠的是"相对固定锚点的单调扩大 + 价值臂的逐轮显著性"。
* **把评测局数拉大来收紧区间**：nn256 在 400 局上约 0.49 局/秒，8,000 局/臂约 4.5 小时——
  在当前"增量远大于区间"的阶段没有性价比。等增量落到 1,000 以下再上。
* **用训练损失/离线指标判断优劣**：负指标（ADR 0030 §3/§5.6），且本轮里它看起来"更好了"
  （策略 CE 从 1.1654 降到 1.0042）而搜索同步在涨——同向也可能是巧合，仍不足以作判据。
* **每轮混入历史数据（replay）以稳定训练**：本轮刻意不混（每轮只学当轮 1M 条），
  用来检验"只学新数据"本身是否稳定。结果是没有出现 ADR 0013 那样的标度漂移（Q̄ 只从 899
  涨到 1490 并趋于平缓），所以"必须 replay 才能防漂移"这个假设本轮**没有**被支持；
  要不要加 replay 应当由"覆盖缺口"而不是"防漂移"来驱动。

## 验证方式

* `python scripts/iterate_monitor.py r1 r2 r3 r4 r5 r6`：复现整张表与全部配对差；
  `--no-probe` 跳过标签诊断。历史轮（r1–r3）的产物名写在脚本的 `LEGACY` 表里，
  r4 起从 `steps/selfplay.json`、`steps/train.json` 自动发现。
* 产物：`exp/g1-r{4,5,6}/`（`runs/{value,policy-head,policy}`、`steps/*.json`、`status.json`），
  数据批 `data/g1-r{4,5,6}-s256-*`，逐局记录 `exp/eval-g1-r{4,5,6}-*.jsonl`。
* 标签诊断的锚点与 ADR 0030 同名量对齐到 3%（同根 std 195.4/166.8/142.4 对 186.2/172.9/145.6）。
* **跨轮可比性的一次直接核对**：这些数字里有些是在 GPU 空闲时测的、有些是在与别的负载共享时测的
  （同一份价值 run 的每轮耗时从 15 s 变成 130 s，慢 8.7 倍）。重跑 r6 的 `nn_mcts-64`（同 checkpoint、
  同协议、同 seed）得到**400/400 逐局完全相同的分数**（均分 13027.5 对 13027.5）——也就是说
  评测结果由 `lanes / in_flight / max_batch` 决定的批组成定死，**与机器忙不忙无关**。所以本表里的
  逐轮比较不会被"当时机器在忙什么"污染；反过来，改这三个旋钮的任何一个都必须当成换协议（ADR 0017）。
* **明确未验证**：
  * 单条线、每轮一个训练 seed（训练级方差未覆盖，与 ADR 0013 的局限相同）；
  * 只评了 64/256 两档，未验证 128/512/1024 是否同样单调；
  * 平台期尚未找到——需要继续加轮（每轮约 40 分钟墙钟）；
  * 与纯 rollout MCTS-1024（ADR 0016 的 27,638，800 局）的配对比较未做。
