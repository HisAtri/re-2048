# ADR 0034：候选排序的两套口径——引擎用 r + A，训练与离线指标用 A；两者之差必须报出来

- 状态：已采纳
- 日期：2026-10-08

## 背景

一次提问把这条链上的一个口径不一致摆上了台面：

> up：合并一个大块，即时奖励 `r = 512`，afterstate 未来价值 `A = 1000`
> left：不合并，`r = 0`，`A = 1200`
> ——按 A 排会选 left，但 up 的预期收益更高（1512 > 1200）

**搜索侧没有这个问题**：引擎的查询值是 `one_ply = edge_reward + afterstate_value * score_scale`
（`cpp/search/batched_engine.cpp:441`），PUCT 里的 Q 也累加 `r + A`
（`cpp/search/rollout_mcts.cpp:210`），同根 min-max 归一化只做平移、不改排序。上面这一手引擎选 up。

而**训练与所有离线指标都在 A 上排序**：

| 环节 | 用的量 | 位置 |
|---|---|---|
| 写数据 | `candidate_value = Q̄(a) − r(s,a)`（= A）；`candidate_reward` 单列存放 | `cpp/dataio/sample.cpp:97` |
| 价值头回归目标 | `batch.candidate_value`（A） | `nn/training.py` |
| 候选 MAE / 成对排序一致率 / 最优候选命中 / 后悔值 | 全是 A | `_Metrics.add_candidates` |
| **checkpoint 挑选准则**（非 policy 模式） | 最优候选命中率（A 口径） | `run_training` 的主指标 |

## 决策

1. **训练目标保持 A，不把 r 加进去。** 这不是"漏了"，而是唯一正确的做法：价值头的输入是
   afterstate `u = T(s,a)`，而 `r(s,a)` **不是 u 的函数**——同一个 afterstate 既能由"合并出 4"
   产生（r=4）、也能由"本来就有 4、只是平移"产生（r=0）。网络原理上无法预测 r+A，r 必须在
   查询时由规则加上。把 r 塞进回归目标或输入特征，会让目标不再只依赖 afterstate、把"已知量"
   交给网络去拟合，并把两个量纲重新焊在一起（ADR 0030 §4.1 量过这种焊死的代价：A 的量级
   缩放 ×10 就让强度从 8,119 掉到 5,988）。
2. **离线指标与看板同时报两套口径**：
   * **A 口径**（原有，保留）＝"价值头把 afterstate 价值预测得准不准"，用于训练诊断；
   * **r+A 口径**（新增，`_Metrics.q_*` / `EpochMetrics.val_candidate_q_*`）＝"引擎会不会选对"，
     与引擎的选择值同口径。
   * `scripts/advantage_probe.py` 的自洽度同时给 A 与 r+A 两列，并新增 `r std 中位` 与
     `r 翻转`（即 argmax(A) ≠ argmax(r+A) 的根占比）。
3. **主指标默认改为 r+A（`value_selection = "q_best_hit"`），旧口径保留为 `best_hit`。**
   先把"改成 r+A 口径"作为独立一轮实验做了，结论是**空实验**（见下：两臂权重逐位相同）。
   **但空实验不构成"不修"的理由**：旧口径量的是"像不像教师的 A"，而引擎的判决取决于 r+A 的
   排序——这是一个**度量错误**，修它不取决于"换了之后成绩有没有变"；空实验说明的是这个错误的
   影响面在该配置下还没显现，不是它没有影响。尺子先修对，再谈影响面。
4. **配套两条工程约束**（都不做会立刻出错）：
   * `model_id` 里**总是**带挑选口径：默认值换过之后，只给非默认值加后缀会让新默认训出的
     `value-<数据>` 与历史上按 A 口径挑出的产物同名——正是 ADR 0030 §5.7 那次事故的形状。
     策略模式不训价值头，口径与它无关，不进名字。
   * **没有候选监督的数据（随机策略批）出声退回价值 MAE**，而不是硬失败：冷启动"在随机
     策略数据上训价值头"是正常用法（ADR 0013/0015），两个排序口径在那里都算不出来。缺席要
     说出来（打印一行），而不是把一条正常路径拦下来。

## 理由与实测

**为什么两套口径都要报：加 r 不改变误差，只改变"谁排第一"。**
`(pred + r) − (target + r) = pred − target`，所以加权 MAE 与后悔值的量级完全不变（测试里钉住了
这条不变量：同一个预测在两种口径下的 `candidate_mae()` 必须逐位相同），**不需要第二套 MAE**。
变的只有排序判决——而这正是"搜索会不会选对"这件事的全部内容。

**暴露面（实测，同根口径）**：

| 批 | std(A) | std(r) 同根 | 自洽度 A | 自洽度 r+A | argmax 被 r 翻转 | r 占 r+A 方差 |
|---|---:|---:|---:|---:|---:|---:|
| r1（greedy 教师） | 196.0 | 3.8 | 0.872 | 0.890 | 3.1% | 0.0% |
| r3 | 145.3 | 3.8 | 0.605 | 0.637 | 11.4% | 0.1% |
| r6 | 99.7 | 3.8 | 0.581 | 0.616 | 12.9% | 0.2% |

* **量级上可忽略**：同根 r 的 std 中位只有 3.8 分（p90 = 20），A 是 96~196，r 只占 r+A 方差的
  0.0~0.2%。
* **判决上不可忽略**：翻转率 3.1% → 12.9%，而且**翻转与决策的重要性负相关**——第一名领先
  >100 分的根里只有 0.8~1.5% 被翻，领先 >500 分的只有 0.1%；按 A 排序的平均 Q 损失是
  2.1~2.6 分/根（翻转根上 20~68 分、p90 152~182）。也就是：**A 排序的错都落在价值几乎并列的
  噪声带里**，而"大合并恰好决定胜负"的场景虽然存在（翻转根上 Δr 的 p90 就是 512），频率是
  千分之一量级。
* **趋势值得盯**：std(r) 恒为 3.8 而 std(A) 从 196 降到 96，所以 r 的话语权在上升（翻转率
  3.1% → 12.9%）。若自举继续把 std(A) 压到个位数，排序就真被"这一手立刻合几分"主导了——
  那正是 ADR 0030 §3 描述的塌缩形态，届时这一节的例子会从千分之一变成常态。

**同根与全局是两个口径，用错会读反结论。** 实测全局 std(r) = 65.0（r1 教师批）/ 81.6（r6），
而同根 std(r) = 3.8。ADR 0030 §3 用"立即得分 r 的 std = 58.8"作参照来论证"A 的同根振幅与
'立刻合几分'同量级"——那是全局口径，与同根的同根 std 不可比；按同根口径，是**价值项主导**
排序（96~196 对 3.8）。ADR 0030 §3 的主结论（同根排序塌缩是退化机制、教师必须给出非循环的
同根估计）不依赖这句话，但该句已按同根口径订正。

## 替代方案

* **把 r 加进价值头的回归目标（训 r + A）**：让目标不再只是 afterstate 的函数，且把两个量纲
  焊在一起（ADR 0030 §4.1 的实测代价）。否。
* **把 r 作为输入特征喂给价值头**：r 未知也能由引擎精确加上，喂进去等于逼网络学一个恒等加法，
  还会让联合/双塔训练的目标语义分叉。否。
* **只保留 r+A 口径、把 A 口径删掉**：A 口径是"价值头预测得准不准"的唯一度量，也是挑选
  checkpoint 的现有依据；删掉它会把"网络误差"和"判决差异"两件事混成一个数。否。
* **立刻把主指标换成 r+A 口径**：会改变已训模型的挑选结果，且当前所有 checkpoint 与评测记录
  都建立在 A 口径上，混改会让"这次变更带来了多少"不可归因。留作独立实验。

## 后续实验：按 r+A 口径挑 checkpoint（已做，是空实验）

配置项 `TrainConfig.value_selection`（`best_hit` | `q_best_hit`）+ CLI `--value-selection`。
处理臂与对照臂**完全同配方**（同数据批 `g1-r6-s256-*`、同 init `g1-r5` 的合并模型、同种子
20261007、8 轮、同架构），只换挑选口径。结果：

| | 对照（A 口径） | 处理（r+A 口径） |
|---|---|---|
| 逐轮 A 口径命中率 | 65.11 / 65.55 / 65.60 / 66.21 / 66.28 / 66.53 / **66.66** / 66.64 | 同左（同一次训练，逐位相同） |
| 逐轮 r+A 口径命中率 | — | 64.72 / 65.21 / 64.82 / 65.45 / 65.25 / 65.59 / **65.84** / 65.81 |
| 选中的 epoch | 7 | 7 |
| `model.pt` 张量 sha256 | `0c319a6f7ee359f8` | `0c319a6f7ee359f8` |
| `last.pt` 张量 sha256 | `efdbdd6a452ead11` | `efdbdd6a452ead11` |

**两臂是同一个文件**：[^1] 两个准则都在 epoch 7 取到最大值；两个口径的逐轮曲线相关 0.93。
原因有两层，第二层才是关键：

1. 挑选准则的取值在最后几轮几乎是平的（epoch 4→8：66.21/66.28/66.53/66.66/66.64，差 0.4pp
   ≈ 150 条验证记录；epoch 7 与 8 只差 7 条）——**现有的挑选本来就在噪声上挑**；
2. 更重要的是：**挑选只能在同一轮训练的不同 epoch 之间选，而这些 epoch 的权重几乎相同**
   （同数据同种子，逐轮只差一次梯度更新）。所以"换挑选口径"这件事的影响上界就是"相邻 epoch
   的差别"，而它对训练信号本身没有任何影响。

**结论：这个错误在 r6 的数据上还没有显现。** 两个口径挑到同一个 epoch，所以两臂是同一个
文件——记下来是为了说明"更换口径"这件事在这份数据上**不改变任何产物**，而不是说旧口径是对的。
它咬的地方在别处（见"下一步"），而"尺子对不上引擎"这件事按决策 3 已经无条件修掉。

**修正后的实测（本次提交）**：默认 `value_selection = "q_best_hit"`，实测默认跑出来的
`model_id` 是 `value-<数据>+q_best_hit`、显式要旧口径则是 `value-<数据>+best_hit`，
两者与历史产物的 `value-<数据>` 都分得开；在随机策略批上训练会打印一行"没有候选监督……
退回价值 MAE"。

## 下一步：口径真正会改变的是"训练目标"，而那是排序项而不是回归项

关键结构事实（本轮实验顺带说清的一件事）：

* **绝对误差对 r 不变**：`(pred+r) − (target+r) = pred − target`，所以 Huber/MSE 这类逐候选
  损失在两种口径下逐值相同——这正是"价值头训 A 就够"的由来（测试里钉住了这条不变量）。
* **但排序的"标签"会变**：成对比较里，A 口径比的是 `target_a vs target_b`，r+A 口径比的是
  `target_a + r_a vs target_b + r_b`——在 r6 的批上两者有 12.9% 的根给出不同的 argmax。
  所以**加一个成对排序项**时，"用哪套口径"是一个真实的选择，不是换度量。

而且 r+A 口径的排序目标有明确语义：`target_Q = r + candidate_value = Q̄`，即**教师自己的边均值
Q 的排序**；而现在的 A 口径训的是 `Q̄ − r` 的排序——一个被立即合并得分扭曲过的视图。搜索的选择
值也是 Q̄，所以**在 Q 空间做排序监督是对搜索输出最忠实的蒸馏**。

这正好是 ADR 0030 §5.3 列过的"同根成对排序损失"，只是当时的措辞没把口径钉在 Q 上（写的是
"同根相对目标"）。ADR 0030 当时把它排在"标签改善之后再上"，而标签确实已经改善
（同根 std 95.6 对旧线的 16.5），前置条件算达成了。

建议的形式（未实现、未测）：保留候选 Huber 作为**尺度锚**（ADR 0030 §4.1 要求量纲显式钉住），
另加一项在 Q 空间的同根成对排序损失（每根 ≤6 对，按访问质量或 Q 间隔加权），两个权重作为
`value_weight` 之外的显式配置项。**风险照旧**：ADR 0030 §4.1 量过"改价值目标会顺带改搜索性格"，
所以这一项必须单独一轮、单独记录，且验收仍是对局（离线指标是反向指标）。

## 验证方式

* `python/tests/test_data_and_training.py::test_candidate_ranking_with_and_without_immediate_reward`：
  两个方向相反的手算根——根 0 是本文开头的例子（A 口径记未命中、白丢 200 分；r+A 口径记命中、
  后悔 0），根 1 是反向（A 口径命中、r+A 口径未命中、按它走丢 312 分 Q）；并钉住"不加 reward 时
  `q_*` 全为 NaN"与"加 r 不改变 MAE"两条不变量。
* `python scripts/advantage_probe.py --batch <批>`：锚点行同时输出两套自洽度与 r 翻转率。
* `python scripts/iterate_monitor.py r1 … r6`：看板同步（探针缓存换版本，避免读到旧字段）。
* 全量测试 62 项通过；`ruff check` 通过。
* **已做**：把 checkpoint 挑选准则换成 r+A 口径——在 r6 的数据上两臂权重逐位相同
  （空实验：挑选只能在同一轮训练的不同 epoch 之间选）；口径本身已按决策 3 无条件改为默认。
* **明确未验证**：Q 空间的同根成对排序损失（未实现，见"下一步"）；自举到 std(A) 个位数时的
  行为（未到）；把 r 翻转的样本单独采样出来人工核对（未做）。

[^1]: 逐一取张量算 sha256（排序后的键、`numpy().tobytes()`），两臂在 `model.pt`（选中的 epoch 7）
    与 `last.pt`（epoch 8）上都相同。这也顺带证明了这条训练路径的确定性：同数据、同 init、
    同种子 ⇒ 逐位相同的权重轨迹。
