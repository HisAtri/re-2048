# ADR 0040：会话里两个"看着正常、玩起来错"的 bug 换来的不变量

- 状态：已采纳
- 日期：2026-10-09

## 背景

WebUI 接上开局之后，人一玩就发现两件事不对：**新块永远落在同一格、而且永远只出 2**；
**终局判定也不对**。两条都不报错、也不崩，只是给出错误的结果——最难发现的那一类。
它们都在会话层（`python/src/r2048/session.py`），引擎与跑谱/训练的路径都没受影响。

## 决策（同时也是要守住的不变量）

1. **引擎的步号就是生成块的随机流**：生成块用
   `derive_seed(引擎种子, kSaltEnvironment, 局号, 步号 + 1, 0)` 播种。
2. **落子之后绝不能 `set_root`**。`set_root` 会把步号清零（它的语义是"盘面被外部改过，
   从一条新的随机流开始"）。会话因此必须把两件事分开：
   * `_replay()` —— 按棋谱重算盘面/得分/步数。**落子走这条**；
   * `_adopt()` —— `_replay()` 之后再把引擎的根局面拉过来。**只有外部改盘面走这条**
     （clear / set / 载入 / undo / 新开一局）。
3. **终局的那一步也是棋**。`play()` 不能因为引擎回报 `terminal` 就把这一步丢掉：
   棋谱是唯一事实源，丢掉它等于界面与引擎差一步。
4. **"空盘面"不是"终局"**。两者都没有合法方向，但下一步动作完全不同（一个要新开一局，
   一个要编辑），所以 `terminal()` 要求盘面上有块，并单独提供 `empty()`。
5. **新开一局要把这一局的种子交给引擎**（`config.seed = 开局种子` 并重建引擎）：
   否则引擎种子固定不变时，每开一局都会得到一模一样的生成序列。

## 理由

* **bug ① 的形态与实测**：会话每走一步重放一次并 `set_root`，步号被清零 → 每一步
  `below(空格数)` 的随机高位与 `one_in_ten()` 抽到的是**同一对**输出。实测 12 步里生成位置
  恒为 1、生成数值恒为 1（只出 2）。修好之后同一段实测：位置覆盖 13/16 格、2000 次开局抽块
  里 190 个 4（9.5%，对得上 90/10）。
* **为什么"位置看起来分散"是个坏判据**（这条是写测试时踩出来的）：
  `below(n) = (随机高位 × n) >> 32`，而 `n` 是空格数、每一步都在变。当随机高位很小时它恒为 0
  （于是永远第一格，bug 就暴露了）；高位较大时它看起来会"散开"，bug 反而被掩盖。
  **我第一版回归测试就是断言"位置分散"，把 bug 放回去照样通过**——那种测试比没有更糟，
  因为它给出的是一条假保证。换成断言**步号在递增**（机制）与**一局之内两种生成值都出现过**
  （行为）之后，才真正有判别力。
* **bug ② 的形态**：`play()` 见到 `terminal` 就 `return`，于是终局那一步既没进棋谱、也没更新
  盘面，界面显示的盘面落后一步却报"终局"。它的另一个症状是**测试挂死**：驱动循环永远等不到
  终局（会话的盘面永远停在终局之前），实测把 pytest 挂到超时。
* **被否定的做法**：① 改引擎让 `set_root` 不重置步号、由调用方传步号——接口更啰嗦，而"盘面被
  外部改过就该从新随机流开始"本身是对的，分清调用时机比改接口更贴合语义；② 给会话另开一条
  "生成块"通道（Python 侧直接调 C++ 的 spawn）——会绕过引擎的对局推进，让"这一步的生成块"与
  "搜索树的推进"脱钩。

## 替代方案

* **让会话自己维护步号并显式传给引擎**：等于把引擎内部的随机流契约复制到 Python 一份，
  两处迟早不一致。现在的做法是"让引擎自己数，会话别去打断它"。

## 验证方式

* `python/tests/test_session.py` 的 "2c. 规则正确性（回归）" 一节：
  * `test_engine_step_advances_across_moves`——落子后引擎步号必须 1,2,3…（**机制**）；
  * `test_spawn_values_vary_within_one_game`——**某一局单独**同时出现 2 与 4（**行为**）；
  * `test_terminal_move_is_written_to_the_record`——棋谱重放 == 会话盘面、末条命令是那一步的
    生成块、终局之后再落子/分析要明确报终局；
  * `test_undo_from_a_terminal_position_restores_a_playable_board`；
  * `test_empty_board_is_not_reported_as_terminal`；
  * `test_same_seed_replays_the_same_game_exactly`——可复现没被上面几条破坏。
* **变异验证（这一步是必须的）**：把两个 bug 分别放回去，对应用例**必须失败，而且失败原因要
  正确**。实测：bug ① 让那两条各自报出"步号没有递增"与"没有任何一局同时出现过 2 与 4"；
  bug ② 让终局那条断言失败（而不再是挂死）。没有这一遍，上面那些断言只是"写过"而已。
* 另一条独立证据：`_drive` 的步数上限是防御性的，但真终局用不到它——一局实测 97~258 步。
