# ADR 0041：记录格式 v3——树内节点块（K 由清单声明），并归档 v2 数据

- 状态：已采纳
- 日期：2026-10-09

## 背景

ADR 0035 的实测把下一步指得很明确：**Q 空间的同根成对排序项只作用在"轨迹根"的候选上，
而价值头在搜索里被直接使用的位置是叶节点与未被访问的边**——那里的 Q 就是 `r + A_θ`，没有
模拟平均来纠错；根那一点有几百次模拟，搜索自己就把排序算出来了（所以"监督根"能显著提升
纯价值贪心臂 +19%，转移给搜索只有 +371~+466，落在标准协议的分辨率之下）。

要监督"价值头真正说了算"的那些位置，需要**搜索树内部决策节点的候选集合**——这是现有数据里
没有的东西。引擎侧的数据其实齐备：`Node` 已经存了 `board` / `legal_mask` / `edge_q_sum` /
`edge_visits` / `edge_reward` / `one_ply` / `edge_afterstate`，根候选块就是从 `root.edge_*`
取的。缺的是**数据通道**。

两条候选路线在讨论中比较过：

* **B：树内节点另存一个数据批**（或 sidecar 文件集）。代价是把"跨流对齐"重新引入一遍——
  而 ADR 0007 合并价值/策略两条流的**唯一**理由就是拒绝跨流对齐（"分成两条流就必须逐 step
  校验动作集合/局号/访问数是否对齐，旧版为此专门写了校验"），并且要复制 ADR 0029 的
  多进程 join 协调（那套所有权/锁/发号机制是按"一个批"设计的）。
* **A：写进同一条记录**。树内节点与根候选是同一次搜索的产物，共享同一个 `(局号, 步号)` 溯源，
  必须一起重放（`verify` 要能逐字节复现），绝不能被错配到别的步上——它在性质上属于
  "这次真实决策的监督材料"，与 v2 的候选块（同样是反事实材料）同类。

**采用 A**（用户判定：旧数据只作理论验证、重建成本低，长期易维护优先）。

## 决策

1. **记录升到 v3**：`基础块（192 字节，偏移与 v2 完全一致）+ K × 树内节点块（每个 108 字节）`。
   **K 由清单的 `tree_nodes` 声明**（0..4），K=0 时记录就是 192 字节。单版本、不猜布局：
   读侧按清单声明的 K 构造 dtype，`tree_nodes` 缺失或越界直接失败。
   * 每个节点块：`legal_mask(1) + count(1) + depth(1) + pad(1) + value[4](int32,16) +
     reward[4](uint32,16) + visits[4](u16,8) + afterstate[4](16×4)`。
   * **不存节点自己的 decision 盘面**：价值头的输入是 afterstate，而 afterstate 就在块里。
   * 实际写出的节点数记在**基础块的保留字节 185**（ADR 0007 留这块保留位就是为这类小字段）。
     不靠"某个槽看起来是空的"推断——那会在边界情况下静默错位。
2. **采集策略：访问数最大的 K 个内部决策节点**（深度 ≥ 1，即不是根），访问数降序、并列取节点
   下标小者。理由：标签可信度随访问数上升（访问数 = 模拟平均的次数），而访问数随深度衰减，
   所以按访问数取等价于取"标签还可信、但价值头仍然说了算"的那一段。**确定性是硬要求**
   （重放校验依赖它）。
3. **它是格式参数，不是逐局协议参数**：采集不改变任何一局的走法（只在搜索结束后读树），
   因此不进 `kProtocolParams`（那批是"会改变逐局结果"的）；但它决定记录字节数，所以
   进清单、**进续跑闸门**（`compare_resume_meta` 比对 `tree_nodes`）、进 Python 的读取路径。
4. **归档 v2 数据、不维护向后兼容**：`output/data` 下的 16 个批次（约 2.8 GB）打包为
   `~/r2048/archive/data-v2-20261009.tar`（抽查 13 个分片的 sha256 与清单一致）并移出工作目录，
   归档说明写在 `archive/README.md`。读取端对版本不匹配**明确失败**（ADR 0007 的闸门），
   v2 数据不再可读；需要时按 `(种子, 参数)` 重新生成（1M 条 4 进程约 11 分钟）。
   **模型 checkpoint 不归档**：它是"权重 + 元数据"，与记录格式无耦合（加载闸门只看
   rules_version / input_encoding / score_scale / 架构版本），仍可加载、可评测、可作教师与续跑起点。
5. **训练侧的消费**：价值头的输入行 = 候选 afterstate **+ 树内节点 afterstate**（并成一次前向，
   不让 GPU 多等一轮）；排序项在根候选与树内节点上一起算，按**候选集合数**归一。
   树内节点只用 `tree_visits > 0` 的边：未访问边的"标签"是教师自己的一次性估计（`one_ply`），
   训它等于让学生复制自己（与根候选用 `candidate_weight > 0` 同一口径）。
6. **多来源混训要求布局一致**（`tree_nodes` 相同），否则直接报错：`gather` 把各来源拼进同一个
   数组，而数组只有一个 dtype——混了 K=0 与 K=2 的批，读出来会错位，那是最难查的一类错误。

## 理由

* **为什么不做 sidecar**：见背景里的 ADR 0007 论证。树内节点与根候选在溯源上是同一个东西，
  分开存只会把"对齐"这件事从"结构性成立"降级成"靠校验维持"。
* **为什么 K 由清单声明而不是固定**：树内块只服务一类实验；固定 +216 字节会让**所有**批次
  （包括 random/mcts 教师批）的记录翻倍，为一个可选通道付永久代价。声明式的 K 让"不采集"
  的批次保持零成本，同时不留第二种猜测路径。
* **为什么按访问数取而不是按深度分层**：先取最保守的一档（标签最实）。分层（每个深度取一个）
  是等价的备选，等这一轮结果出来再决定要不要换——把它写在这里是为了下次不必重新推演。
* **为什么归档而不是兼容**：兼容要长期维护 N 个读取器，"单布局"这个简洁性就没了；而重建
  数据在本项目的成本是分钟级（且 `verify` 的重放承诺让"重建的数据可信"这件事有依据）。

## 替代方案

* **B：树内节点另存一批 / sidecar 文件集**：见上。
* **固定 K 而不由清单声明**：所有批次为可选通道付永久字节成本。
* **把节点自己的 decision 盘面也存下来**：多 16 字节/节点且无用途（价值头的输入是 afterstate）。
* **读取端同时接受 v2/v3**：历史批次继续可读，但格式演进开始要维护多读取器。用户判定旧数据
  只作理论验证，故不采用。
* **把树内节点也用于策略头/价值回归的绝对误差**：本轮只做排序项与检测（见下"未验证"）。

## 验证方式

* `cpp/tests/test_dataio.cpp::dataio_sample_roundtrip`：K=0 与 K=2 的逐字段往返、含负值；
  `sample_bytes(2) == sample_bytes(0) + 2 × kTreeNodeBytes`；基础块偏移不变（K=0 仍是 192 字节）；
  185 记录实际节点数、186..192 仍为 0。
* `python/tests/test_data_and_training.py::test_ranking_loss_covers_tree_nodes`：树内节点**参与**
  排序项（把它的排序预测搞错损失上升）；未访问边**不参与**（访问数为 0 的边搞错也不罚）；
  没有树内块时（`tree_prediction=None`）行为与从前一致。
* 端到端：生成一批 K=2 的数据（`schema_version=3`、`tree_nodes=2`、`record_bytes=408`）；
  逐条核对树内块的结构（`count == popcount(legal_mask)`、非法方向访问数为 0、深度 ≥ 1）；
  **同配置生成两次，逐分片 sha256 一致**（同时证明树内块是确定性的——NN 批的可复现性检查
  在 Python 侧，`r2048 verify` 的 C++ 重放只认 random/mcts，见 ADR 0007 §7）。
* **"改了参数却没生效"的闸门**：`run_selfplay_workers` 在收尾后核对产物清单里的格式参数与请求
  是否一致，worker 没产出清单时直接报错并指出日志路径。这条闸门是被真实的坑逼出来的：第一版
  把 `--tree-nodes` 只挂到了 `iterate` 的解析器上，worker 的 argv 里带了它而 `selfplay` 子命令
  不认，于是 worker 启动即失败——表现出来是"父进程毫不知情地继续"，而修复前的那一轮更隐蔽：
  K 被静默地当成 0，整批数据少了一块、训练照跑（与 ADR 0034 的"默认值改了却不生效"同一类）。
* 全量：`ctest` 6/6；`python/tests` 137 项；`ruff check`。
* **明确未验证**：树内节点监督相对"只监督根"的增益（下一轮实验，验收用校准好的仪器：
  8/16/64 模拟各 4000 局）；K 的取值（本轮 K=2，K=4 或分层选取未测）；把树内节点用在
  价值回归的**绝对误差**上（而非只做排序项）未测。
