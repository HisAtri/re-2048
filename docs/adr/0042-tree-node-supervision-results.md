# ADR 0042：树内节点监督的首轮实测——真实但微弱（+105，跟预算无关），且贪心臂反而变差

- 状态：已采纳（结果 + 默认选择：**格式保留，但 `--tree-nodes` 默认 0**）
- 日期：2026-10-09

## 背景

ADR 0041 把"价值头在搜索里真正说了算的位置"（叶节点与未被访问的边）变成了可训练的数据：
记录 v3 的树内节点块。这一轮回答它有没有用，以及值不值得付它的代价。

对照臂是 **rank-r6**（同一批棋局、同一 init、同一种子、同 8 轮，只有"排序项监督在哪"不同）：

* rank-r6：排序项只覆盖**轨迹根**的候选（数据是 v2、K=0）；
* tree-r6：排序项覆盖**轨迹根 + 2 个树内节点**（数据是 v3、K=2，`tree-r6-s256-20261009-110431`）。

两臂的差异**只在价值半**：策略半的配方与数据无关（策略头只吃决策局面），且训练是确定性的，
所以两半的差异归因是干净的。

|---|---:|---:|---:|---:|---:|

## 读法

1. **机制成立但增量小**：+105 分在 64 模拟上相当于 +0.8%（评分标尺约 +1.8 分），是"只监督根"
   那一步（+371~+466，评分约 +7~16 分）的约 1/4。**树内节点的信息量确实低于根**——这与
   ADR 0041 的选取策略（按访问数取、即标签最实的那几个）一致：访问数越大，标签越像"搜索
   自己算出来的"，越不构成对价值头的新信息。
2. **它换的是"搜索的判断"而不是"贪心的判断"——而且这个取舍被判定下来了**：贪心臂
   **−514（显著，4000 局）**，搜索臂 **+105（显著，20000 局）**。贪心臂是"完全由价值头的排序
   决定"的那条臂，所以这是**同一个头在两个口径上朝相反方向移动**：把监督面从"轨迹根"挪到
   "搜索树内部"之后，它更懂搜索会怎么用自己，而更不懂无搜索的贪心该怎么走。方向与设计意图
   一致（监督打在搜索使用价值头的位置），但它同时给出两条纪律：
   * **纯价值臂不能当作"监督类改动"的先行指标**：ADR 0030 §6.3 把它验证为**标签质量**的指标，
     而这一轮改的是监督**位置**——这里它指的正是反方向。监督类改动要用低预算 + 多局数的
     搜索臂（ADR 0033 的分辨率纪律）。
   * 如果一个改动的目标是"纯网络下得更强"（例如给界面用的快速策略），树内节点监督是**反向**的。
3. **代价是实的**：记录 192 → 408 字节（2.1×，跑谱产出、存储、训练读盘都翻倍），价值头的
   前向行数 ×3（4 个候选行 + 8 个树内节点行）。用一个 ~+105 分（评分 +1.8）的增量换这个代价，
   在"绝对水平"这个轴上不划算。
4. **所以默认关闭**：`--tree-nodes` 默认 0（格式与实现都留着，K 由清单声明，不采集时零成本）。
   `value_ranking_weight=1`（ADR 0035 的根监督）保持默认开——它零存储成本、不增加前向行数，
   而增量是这一步的 3~4 倍。

## 决策

1. 记录格式 v3 与树内节点块的实现**保留**（ADR 0041）：它是"搜索真正使用价值头的位置"上唯一的
   监督通道，默认 K=0 时零成本，任何后续实验都可以一键打开。
2. **跑谱与迭代的默认 `tree_nodes = 0`**：这条线的常规轮次不付 2× 数据与 3× 价值前向的代驾。
3. **贪心臂不再作为"监督类改动"的先行指标**：它的验证范围是标签质量（ADR 0030 §6.3），不是
   监督位置。监督类改动用低预算 + 多局数（ADR 0033 的分辨率纪律）。

## 替代方案

* **K=1 或 K=4**：K 越小代价越低、信息越少。K=1（记录 300 B、前向 ×2）可能拿到大部分增量，
  未测——它是"想再要那 +105 又要省一半代价"时的第一个候选。
* **按深度分层取节点**（每个深度一个）而不是按访问数取 top-K：ADR 0041 里列为等价备选。
  按访问数 = 标签最实但最像搜索自己；分层会带进更深的、更"价值头说了算"的节点，但标签也更吵。
  **读法 1 说明"信息量低"可能正是选取策略造成的，所以这一条现在是首选后续实验。**
* **把树内节点也用于价值回归的绝对误差**（不只是排序项）：未测。
* **靠加大 K 继续压**：按读法 1，边际信息递减，不优先。

## 验证方式

* 两臂同数据/init/种子、只差监督面：`tree-r6`（`exp/tree-r6/`）对 `rank-r6`（`exp/rank-r6/`）。
  离线指标见 `runs/value/train.json`，对局见 `exp/eval-{rank,tree}-r6-*.jsonl`。
* 数据侧：`tree-r6-s256-20261009-110431` 的清单声明 `tree_nodes=2 / record_bytes=408`；
  树内块的结构核对（`count == popcount(legal_mask)`、非法方向访问数为 0、深度 ≥ 1）。
* **明确未验证**：增量是否随 K 或"分层选取"变大；树内节点用于回归项；更高预算（256/512）下
  是否仍然 +105；单轮一个训练 seed。
