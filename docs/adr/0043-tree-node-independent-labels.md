# ADR 0043：树内节点的独立标注（记录 v4）——把监督面补到查询面的那一半

- 状态：已采纳（格式 + 机制）；步骤 A/B 的实测另记
- 日期：2026-10-09

## 背景

ADR 0042 量到树内节点监督只有 **+105**（显著，20000 局），并给出机制解释：按访问数取 top-K 等于
取"标签最实、也最像根"的那一段。缺的另一半是明确的：

* **头的查询面 >90% 在搜索树内部**（根只占 1 个决策节点），而监督面曾经只有每步一个根 ——
  训练分布与部署分布错配（ADR 0015 修的是同一件事的上一层）。
* 但**低频/深层节点的树内标签约等于头自己的输出**：那里 `Q̄ ≈ one_ply = r + A_θ`，拿它当监督
  等于让学生复制自己（ADR 0030 §3 的循环下沉一层）。这是数学边界，**不能靠多放字节解决**。

所以要覆盖"头真正说了算"的位置，必须给那些状态一个**不依赖头的标签来源**——这正是 ADR 0030 §5.1
证明过的杠杆（教师必须给出非循环的候选估计）在树内节点上的同构应用。

（**成本估算被实测否掉，见验证方式**：初版按 3860 样本/秒反推 playout ≈ 4 µs、标注开销 +9%，
实测吞吐从 ~1300 样本/秒降到 ~160——标注开销是搜索本身的约 8 倍。原文如下，保留以示估算错在哪：
一次 playout ≈ 4 µs（按 ADR 0030 的 greedy 教师 3860 样本/秒、64 模拟/样本反推），
K×4 边×R=8 次 ≈ 0.5 ms/步 ≈ 9 分钟/百万条。

## 决策

1. **续弈策略抽成共享原语**（`cpp/game/continuation.h`：`continuation_action` / `playout` /
   `greedy_continuation`），`RolloutMcts` 改为调用它。理由：ADR 0030 §6.1 实测续弈策略是标签
   信息量的**直接决定因素**（均匀 → 一步启发式使同根 std ×3.4、学生强度翻倍），两份实现迟早会漂。
2. **生成侧对抽样到的内部决策节点做独立标注**：对每条合法边的 afterstate，先补一个随机块
   （A(u) 的定义里块在决策前生成），再用规则驱动的续弈策略走到终局，取 R 次均值。
   * 随机流：新增 `kSaltTreeLabel`，`derive_seed(seed, salt, episode, step, index)`；
     **`index` 只由静态量构成**（槽位、方向、副本）——不许用访问数/在途数这类取决于交付时序的
     计数（ADR 0031 记过 `pending.size()` 当 index 的后果）。这是重放与两次生成一致性的前提。
   * 抽样策略：默认**按深度分层**（每个深度取访问数最大的那个节点，K = 覆盖的深度数）。头的
     查询面遍布各深度，而 top-K 会把槽位全堆在浅层（那里最像根、信息最冗余）。保留 `top_visits`
     作为对照——步骤 A 用它以**隔离标签来源**这一个变量。
   * 续弈策略默认 greedy（ADR 0030 §6.1 证实更强），可用 `uniform` 对照。
3. **记录 v4**：树内节点块增加 `rollout_value[4]`（int32，原始分数单位）→ 每节点 108 → 124 字节。
   `value[4]`（搜索自己的 Q̄ − r）**保留**。于是**一批数据同时带两种标签**：A/B 只需训练侧开关、
   可比性由构造保证，并且"两者的相关"本身就是这个闭环有多紧的读数。
   版本闸门 v3 → v4（ADR 0007 的纪律），v3 的唯一一批随之归档。
4. **参数归属按既有边界**：`tree_label_policy` / `tree_label_plays` / `tree_label_rollout` 都不改变
   任何一局的走法（标注发生在搜索结束之后）→ 像 `tree_nodes` 一样走"独立 `BatchMeta` 字段 +
   清单 + 续跑闸门"，**不进** `kProtocolParams` / `SOURCE_KEY_PARAMS`。与 `rollout_policy` 是
   两个角色：那个驱动纯 C++ 教师的**搜索**（因此是协议参数），这个只用于**标注**。
5. **训练侧**：新增 `tree_label_source`（`rollout` 默认 | `qmean` 旧口径）——排序项用哪种树内标签。
   两个口径对"未访问的边"的处理不同，这正是 v4 存在的理由：`qmean` 在访问数为 0 时就是 pure
   one_ply（必须排除），`rollout` 与访问数无关（应当参与，那正是头说了算的区域）。
   标签来源**总是**进 `model_id`：默认值换过（qmean → rollout），只给非默认值加后缀会让新旧两份
   不同权重同名（ADR 0030 §5.7、ADR 0034 都踩过这个形状）。
6. **默认**：`tree_nodes=2`、`tree_label_plays=8`、`tree_label_policy=depth_stratified`、
   `tree_label_rollout=greedy`、`tree_label_source=rollout`。一致性优先于成本（ADR 0042 的订正）。

## 理由

* **为什么标签必须独立**：见背景的第二点。树内 Q̄ 在低频节点上不是"另一个估计"，而是同一次前向
  的返回值——用它做监督不产生任何新信息。
* **为什么两种标签并存而不是替换**：替换就无法在同一份数据上做单变量 A/B，也无法量化"搜索自己的
  Q̄ 与独立估计差多少"（= 闭环的紧度）。多 16 字节/节点换这两件事，值。
* **为什么分层而不是加深 top-K**：读法已说明 top-K 方向的边际信息递减（ADR 0042 读法 1），而
  分层把监督铺到 `one_ply` 直接决定 Q 的深层。
* **为什么续弈策略只留一份**：它同时决定"教师搜索的估值"与"独立标签的估值"；两份实现漂开之后
  同一批数据里的标签口径就不再是一个东西，而它看起来仍然正常。

## 替代方案

* **用深层搜索或"当前头 + 精确 chance 期望"当树内标签**：仍是头自己的回声，循环未解。
* **只按深度分层、不换标签来源**：那只是把回声铺得更散（本 ADR 的前一版想法，已被否）。
* **把 R 次 playout 的方差也存下来**（做可靠性加权）：+8 字节/节点，留到 v5——本轮先用等权均值，
  但诊断里要交代噪声（见验证方式）。
* **兼容读 v3**：为一批只存在了几小时的数据维护第二个读取器不值；按 ADR 0007 抬版本、归档。

## 验证方式

* **续弈抽取的行为等价**：用归档的 v2 纯 mcts 批（`mcts64-s20261007`，seed 20261007 / 64 模拟 /
  16 worker）逐字节比对：同参数重生成 200000 条，**基础块前 100000 条与归档批逐字节一致**——
  这是"重构没改行为"的直接证据。
* **格式**：K=2 记录 440 字节、`tree0_rollout` 偏移 300 的两处自检（C++ 的 `sample_bytes` 与
  Python 的 `record_dtype` 各自一致）。
* **确定性**：同配置两次生成（K=2、`top_visits`、R=8）**逐分片 sha256 一致**——同时证明独立标签
  的随机流派生是顺序无关的。
* **清单声明**：`schema_version=4 / tree_nodes=2 / tree_label_policy=1 / tree_label_plays=8 /
  tree_label_rollout=1 / record_bytes=440`；续跑闸门比对三个标注参数。
* **探针诊断**（4000 条、K=2、`top_visits`、R=8）：槽位有标签 3985/4000；同根 std：树内 Q̄
  ≈102 分、独立 playout ≈307 分；两者逐槽位相关 **0.746**（非零 14266 槽）。
  **诚实交代**：307 里含 R=8 均值的估计噪声（每边 8 次 playout），ADR 0030 §6.5 的
  "表观 std = √(信号²+噪声²)"在这里同样适用，所以不能直接读成"信号更大"；相关 0.746 说明相当
  一部分是共同信号。要判定独立标签的信号量需要逐边的 playout 方差（v5）。
* 全量：`ctest` 6/6；`python/tests` 137 项；`ruff check`。
* **明确未验证**：步骤 A（只换标签来源，K=2/`top_visits`）与步骤 B（换成分层 K=4）的 A/B 效果；
  回归项也用树内节点；R 的取值（本轮 8）。
