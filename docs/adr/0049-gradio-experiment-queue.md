# ADR 0049：Gradio 实验队列、停止恢复与对局资源占用

- 状态：已采纳
- 日期：2026-10-10
- 补充：ADR 0039、0045、0047、0048

## 背景

跑谱、双头训练和评测都是长任务。直接在 Gradio 回调中执行会使计算生命周期依赖
浏览器请求，而且长生成器会阻塞停止操作。对局推理同时占用 GPU 也会影响实验性能。
身份、谱系、发布与评分已有工作流，界面应复用这些规则。

## 决策

### 持久化队列与进程

输出根 `jobs/job-YYYYMMDDNNN/` 保存不可变的 v1 `request.json`、原子替换的
`status.json`、`result.json`、有界展示的 `worker.log` 和 `work/` 阶段产物。
UTC 身份由公共发号器分配。确认同一份预览使用同一提交 token，重复点击返回原任务。

一个输出根只允许一个服务器队列管理器持有 `jobs/.manager.lock`。长任务按入队顺序
串行执行，通过 argv 数组启动 `python -m r2048.webui.worker`，不执行 shell 字符串。
任务内部沿用 C++ 并行与多 worker。单个任务失败不会退出调度循环。
状态为 queued、running、stopping、stopped、finished、failed、cancelled、interrupted。
继续操作复用任务目录和请求，在队尾重新入队；排队任务可以取消。

浏览器只订阅状态，至多每秒一次、只发送变化与最多 100 行/64 KiB 日志尾部。
浏览器关闭不停止任务。正常关闭服务器写入停止指令并等待当前任务保存退出，排队请求
保留。重启时仅在 `/proc` 中同时验证 PID、进程创建时间、任务目录和提交 token 后接管
工作进程；无法验证则标记 interrupted，供用户继续，不凭 PID 杀进程。

2026-10-10 订正：独立任务会话必须由工作进程通过 Linux pidfd 监护服务器实例。
服务器异常退出（包括 SIGKILL）后立即写停止指令，最多等待 60 秒保存；超时将状态写为
interrupted 并清理任务自身的独立进程组，避免跑谱子进程继续占用计算资源。
超时清理可能丢失尚未提交的棋局或训练批，只能从已经持久化的断点恢复。
浏览器断开与服务器退出分别处理，浏览器关闭仍不影响任务。

多 worker 在导入 torch/BLAS 之前设置 OMP、MKL、OpenBLAS 线程数为 1，运行阶段继续
固定 torch intra-op 线程数为 1。基准使用相同启动环境。不能把 CPU 满载一概归因于
线程池：独立树内续弈标注也在 CPU 上执行，应查看搜索/标注耗时再判断。
各 worker 每 0.5 秒写独立原子遥测，监督进程聚合模拟数、搜索吞吐和搜索/标注耗时占比。
manifest 仍是已经提交样本的唯一来源；首批完整棋局提交前显示搜索活动，不能把零条
已保存样本描述成没有运行。模拟数不折算为完成样本或伪造样本 ETA。

### 停止与阶段提交

停止/取消回调绕过 Gradio 长任务队列。统一 `control` 文件传递停止意图。
跑谱在局边界停止并提交 manifest，清除遗留指令后继续原批。
训练在优化器更新后的批边界保存 `last.pt`、优化器、调度器、随机数及完整累计谱系。
若训练轮已结束而验证被中断，保存 pending_epoch，继续时仅重做验证，避免重复更新权重。
停止后的训练不合并、不发布。双头工作流对合并产物保存完成记录和摘要，发布前崩溃
恢复复用同一产物；正式发布复用预留发布身份。

首轮策略头以本轮价值半模型初始化时，合并后该价值半模型的数据属于本轮规模；继承
规模只取它的祖先。以半模型 ID 和 SHA256 确认内部初始化关系，`merged_from` 仍保留
物理初始化路径与摘要。因此从头进行双头训练的正式发布继承规模为零。

评测在局边界停止，未完成评测不提交 JSONL，也不导入评分池；完成的各条臂保留标记。
恢复只重做未完成臂。评分在公共文件锁内先校验请求，再原子替换评分池与锚点文件。
发布和评分是短提交，停止在其前后处理，不中断一次提交。
重做选择的上游使下游记录及预留身份失效一次，继续同一重做任务不再次失效；旧发布保留。

### 共享工作流与资源

独立训练与迭代共用 `workflows/dual_training.py`：价值训练、冻结价值的策略训练、合并。
评测与评分共用 `workflows/assessment.py`，正式模型的评测标签采用发布身份。
搜索评测附同预算纯 MCTS，纯网络附随机基线；只初始化缺席的评分线锚点，更换已有
锚点必须通过显式设置操作。缺锚点时显示模型统计，评分及区间留空并说明原因。

队列启动任务前请求自动对局停止，等待持有对局锁的一次分析/落子结束，然后取得计算权。
占用期间服务端拒绝新分析、推理落子和模型连接；棋盘、编辑、复盘保持原状态。
任务退出释放占用权。产物清单刷新不会自动连接或更换对局模型。

Gradio 保留为可选依赖，默认监听 `127.0.0.1`，没有额外数据库或外部服务。

## 理由与替代方案

- Gradio 回调内计算使刷新/断线与任务取消耦合，也无法在重启后恢复队列，故使用子进程。
- 每浏览器一条队列会造成 GPU 争用和重复提交，故输出根用一把服务器锁、一个长任务槽。
- 强制 terminate 无法保存优化器和随机数，也可能丢失整局数据，故采用合作式停止。
- 仅保存 epoch 编号无法分辨“训练完但未验证”，会重复优化；批位置和 pending_epoch
  将这两种断点明确区分。
- 多任务 GPU 调度、外部数据库和消息服务尚无必要，第一版采用持久 JSON 与文件锁。

## 验证方式

WSL 中构建 C++，集中运行 Python/C++ 回归。`test_experiment_tasks.py` 通过真实子进程
验证并发提交去重、取消、失败后继续调度、跑谱停止/重启/恢复、完整迭代和独立继承训练。
训练器对训练批和验证阶段停止分别验证恢复权重逐张量一致、随机状态及累计谱系保留。
WebUI 回调验证输出数量和参数校验，实际启动本地服务器，经 Gradio HTTP 客户端完成
配置预览、重复确认去重、完整迭代发布评分、任务详情订阅与产物选择。
实际发送 SIGINT 关闭服务器，确认当前跑谱安全停止、排队任务保留；重启管理器后先执行
排队任务，再继续原停止批次，批次身份保持不变。
初次桌面浏览器连接受 WSL 回环端口转发限制。随后通过双方仅监听本机回环的临时转发
完成浏览器检查，未扩大网络监听。页面布局与参数归属由 ADR 0050 订正。
