# ADR 0050：实验工作台的页面边界与任务视图

- 状态：采纳
- 日期：2026-10-10

## 背景

初版将操作表单与任务队列、JSON 详情长期并排，压缩主内容宽度；训练设置放在公共
区域，使跑谱和评测也显示训练方案。完整迭代读取其他标签页参数，用户难以确认本次配置。

## 决策

- 跑谱、双头训练、评测与评分、完整迭代和任务分别占用独立标签页，操作页使用全宽。
- 各操作只读取本页组件；完整迭代独立配置跑谱、训练、评测，后台仍调用共享工作流。
- 跑谱仅在选择模型教师时显示推理设备；纯 MCTS 使用 CPU。评测设备是推理设备，
  训练方案、轮数、批大小仅位于训练与完整迭代页。
- 参数检查生成冻结请求与中文摘要。手动修改输入或切换页面会使摘要失效，确认按钮
  在有效检查后才启用。同一冻结请求沿用原提交 token，保留去重语义。
- 任务页使用中文状态、阶段和实际进度字段，展示累计去重规模；日志默认折叠。
  评分显示可读协议摘要及短协议编号，95% 区间按评分加减原置信半宽计算。
- 模型选择展示模型名，数据选择使用稳定批次身份，状态和样本数作为展示信息。
- 训练配方直接展示原始文件 ID（如 `double-tower.yaml`），不使用“双塔默认方案”这类
  无法唯一标识配方的别名。冻结请求保存配方 ID 与配置快照，摘要分别展示配方 ID 和
  原始架构 ID（如 `smnet-b9c64dt`）；新增配方或双塔定义仍按各自 ID 区分。

## 验证

在 WSL 启动 Gradio；桌面浏览器通过临时本机回环转发访问 WSL 回环监听，检查各页布局
和按钮交互，不扩大网络监听。组件回归检查页面归属、预览输入的页面边界、回调返回数、
任务进度与评分区间。运行队列与计算工作流的语义沿用 ADR 0049。
