# ADR 0051：统一加载本机实测性能参数

- 状态：采纳
- 日期：2026-10-10

## 背景

旧版本 ADR 0017 已实现 benchmark 与机器画像，当前项目遗漏了迁移，CLI、迭代与 WebUI
仍各自填写固定默认值。旧版 Windows 画像和无独立标注的基准不能代表当前 WSL、R=8
标注的成本；仅根据 GPU 利用率推测调度架构问题没有充分依据。

## 决策

- `performance.py` 为共同参数入口，优先级为显式参数、匹配的实测画像、原默认值。
  CLI 支持 `--performance-profile auto|off`；WebUI 默认使用自动模式，取消后手动指定。
- 画像存于输出根 `benchmarks/machines.json`，版本为 1，使用文件锁与原子替换。
  指纹包含 CPU、核心数、OS、Python、PyTorch、CUDA、GPU 和内核 build ID。
  工作负载包含架构及完整尺寸、阶段、FP32 和搜索/标注参数；训练另区分 mode 和冻结状态。
  不自动读取旧项目的画像，不跨机器、架构或标注配置套用建议。
- 不把所有参数都称为性能旋钮：模拟预算、树内标注、训练目标、学习率和精度保持配方定义。
  可加载项为 worker 数、并行局数、在途数、推理批上限和训练批大小。
  搜索批组成会影响逐局结果（ADR 0017/0031），有效值仍写入原有协议与续跑闸门。
- `python -m r2048 benchmark probe|show` 提供当前项目的入口。NN 跑谱直接使用当前 C++
  引擎与批推理器，多进程启动完成后同步开始计时；按固定工作负载的模拟吞吐选择 worker，
  近似同速选较少进程，遇显存不足停止扩张。纯 MCTS 测真实 C++ 生成吞吐。
  评测测同形状预热后的编码、前向和回传吞吐，仅推荐批上限；训练用真实数据前缀跑一轮，
  按训练样本吞吐选择批大小。二者不承诺提高 GPU 利用率或模型质量。
- benchmark 检查已验证的后台计算任务；有任务运行时拒绝测量，不自动停止用户任务。
  正式工作流不隐式运行 benchmark。没有画像时显示回退原因。
- WebUI 在检查配置时解析并冻结实际值及来源，所有浏览器提交同一份结构化请求。
  CLI 跑谱保存 `performance.json`，续跑复用原协议值；迭代保存在 `iteration.json`；
  训练在 checkpoint 的配置与报告保存来源，恢复时保留批大小。
- 多 worker 父进程只读取模型身份，GPU 权重由工作进程加载，避免监督进程占用额外一份
  模型。子进程显式传 `--workers 1`，避免再次加载画像而递归扩张；`--join` 同样默认单进程。

## 验证

在 WSL 实际运行 CPU 的 NN 跑谱、纯 MCTS、评测推理和短前缀训练 benchmark，并检查
画像读取、显式覆盖、off、标注配置隔离和 WebUI 摘要。按当前正式模型、64 次模拟、
64 lanes、in-flight 8、K=2/R=8 的 GPU 基准扫描 1/2/4/8/16 个 worker，分别得到约
按生产方式共用批次与跨进程局号，得到约 9858/19581/36567/57547/69358 模拟/秒，
本机画像选择 16。此结果是本次短基准吞吐，
不是正式长跑验收，也不是整张 GPU 的利用率。

2026-10-10 补测：统一启动前的 OMP/MKL/OpenBLAS 单线程约束后，4/8/16 worker
短基准分别约为 36936/58721/70077 模拟/秒，画像仍选择 16；不能据此承诺 GPU 满载。
正式任务的搜索进度与服务器异常退出清理由 ADR 0049 的订正规定。
随后消除贪心续弈的重复移动计算（ADR 0043），同配置补测约 74689/109194/145606
模拟/秒，画像已经更新为这一结果，仍选择 16 worker。
