# ADR 0052：固定测评配置、共享基线与自动随机种子

状态：已采纳

## 动机

WebUI 每次评分给纯 MCTS 分配任务身份并重跑，造成评分池内多份基线；可编辑的
局数、搜索预算与自动性能画像也让同名测评的口径不明确。

## 决策

- 训练配方改名为 `smnet-b9c64dt.yaml`，文件名与正式架构一致。
- WebUI 跑谱、训练及训练/验证划分默认种子为 `-1`。运行时用系统随机源生成实际
  非负种子并持久化；停止恢复沿用实际种子。显式非负种子仍可复现。
- 双头训练共享划分种子，策略头用价值头种子加一，避免验证集泄漏及相同增强序列。
- 测评配置位于 `configs/assessment/`，首版 `P1000S64` 固定 1000 局、64 次搜索，
  种子即时随机生成。推理设备、批组成、缓存与探索系数也固定，不采用性能画像覆盖。
  WebUI 单独评分与完整迭代共用该配置；CLI 的自由评测保留。
- 配置发布后不改写，新增口径使用新 ID。基线身份包括完整配置摘要、规则/协议版本
  及纯 C++ 策略参数；首次完整生成后跨任务复用纯 MCTS 基线。
  跨进程锁防止首次并发重复生成，未完成基线不提交完成标记。
- 模型每次评测独立抽样，基线种子独立生成并保存。评分沿用既有独立双样本区间，
  不将缓存基线与新评测当作同种子的配对样本。历史评分池及已设置锚点不自动改写。

本决策替代 ADR 0049 的 WebUI 每次附带重评基线和 ADR 0051 的自动评测参数建议。

## 实现纠正

初版实现擅自加入随机落子基线和直接选招评分，偏离用户要求，已撤回。
`P1000S64` 在文件中声明 `track: nn_mcts` 和唯一 `baseline.policy: mcts`；
WebUI 单独评分与完整迭代都只生成这两条搜索臂。该纠正保留已有纯 MCTS 缓存身份，
清除误加的随机基线、锚点与评分记录。1000 分沿用已有相对标尺，以纯 MCTS 为基准。
