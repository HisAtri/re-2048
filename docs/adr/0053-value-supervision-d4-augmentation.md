# ADR 0053：补齐价值监督输入的 D4 增强

- 状态：已采纳
- 日期：2026-10-11

## 背景

ADR 0010 的 D4 增强只处理了决策局面与主轨迹 afterstate。引入候选级价值监督和树内排序监督后，前向输入改为 `candidate_afterstate` 与 `tree_afterstate`，这两类棋盘绕过了增强。默认候选配方因此没有给价值头提供 D4 增强。

## 决策

在训练循环组装价值前向行时，对根候选与实际送入网络的树内候选逐行施加随机 D4 变换，复用现有设备端 `augment_value`。保留槽位顺序，不重排价值标签、立即奖励、访问权重、合法性与排序配对。

每条价值监督的标签都是对应 afterstate 的标量，D4 不改变其含义，因此不同候选可以独立变换，无须与策略头共享朝向。策略棋盘、合法掩码与策略标签仍使用同一个变换；主轨迹沿用现有增强，避免重复增强。验证集及 `augment=False` 均保持原输入，合并一次前向的机制不变。

## 影响与验证

无需重建数据或迁移 checkpoint。新增增强消耗现有 checkpoint 已保存的增强发生器随机数，修复后的续跑仍可复现，但不会复现修复前未增强候选的训练轨迹。

`test_epoch_augments_all_value_inputs` 在真实 epoch 循环中观察前向棋盘，覆盖 value/joint/dual、候选/主轨迹、K=0/K=2、开启/关闭增强及验证模式；逐行检查 D4 轨道及槽位对应关系，并验证原批次未被修改、损失有限且仍仅有一次前向。

在 WSL `Ubuntu_22_04_Cuda` 的现有 Linux 环境中运行数据与训练测试文件，70 项全部通过（含现有断点续跑回归）；本次涉及的两个 Python 文件通过 Ruff 检查。
