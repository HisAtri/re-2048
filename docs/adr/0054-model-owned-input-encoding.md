# ADR 0054：模型定义拥有输入编码

- 状态：已采纳
- 日期：2026-10-11

## 背景

ADR 0003 将编码集中在 Python，以避免 C++ 与训练输入分叉。但 ADR 0024 的模型边界进一步固定为 `(N,25,4,4)`，训练、推理和加载器均依赖全局 one-hot 编码，使新模型无法只在定义内部更换输入表示。

## 决策

本决策替代 ADR 0003 的全局编码位置与 ADR 0024 决策 6 的已编码输入边界，保留跨语言传原始棋盘、按定义注册与历史模型计算语义不变的要求。

- 统一 `forward(boards)` 接收 `(N,16)` 原始指数整数棋盘，调用端只负责批组成、设备传输与 AMP 上下文。编码、通道数和特征内存布局均由模型内部决定。
- 两个现有模型显式选用 `components/exponent_one_hot.py` 的原编码，保留编码标识及全部参数键名和形状；编码工具没有参数，不给旧权重添加前缀。新模型可直接实现自己的编码，无须继承现有工具。模块职责划分见 ADR 0055。
- 不增加模型编码声明接口。已有 `input_encoding` 元数据的写入与加载校验保持原实现；本次仅移动编码执行的位置，不重设计产物格式和校验机制。
- 卷积模型内部根据 stem 权重布局选择编码特征的 channels_last 布局，保留训练配置现有的模型布局设置；不向公共 forward 增加卷积专属参数。
- 推理计时将原来的外部 `encode` 阶段改为 `transfer`，编码纳入模型前向及 GPU event 的测量范围。自对弈报告字段对应改为 `transfer_seconds`。
- 未被调用的 `encode_numpy` 删除；前向辅助函数改名为 `forward_boards`。C++、数据格式、D4 增强与损失不变。

## 验证

用旧编码公式与两版网络的既有层路径对照原始棋盘接口，检查通道布局开关、超出 one-hot 截断范围的指数、checkpoint 往返及输出逐张量等价。测试注册一个不用 one-hot 的模型，覆盖元数据、加载校验、训练反向、批推理、辅助前向和探针。另在 CUDA 上检查 AMP、channels_last 与实际 torch.compile 的前向和反向。

WSL `Ubuntu_22_04_Cuda` 验证结果：模型、数据与训练、合并及固定测评测试 96 项通过；真实自对弈、发布与迭代发布链路测试 8 项通过，无跳过。涉及的 Python 模块通过 Ruff 检查，Git diff 无空白错误。
