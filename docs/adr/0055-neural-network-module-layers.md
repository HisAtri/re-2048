# ADR 0055：网络定义、复用组件与模型管理的分层

- 状态：已采纳
- 日期：2026-10-11

## 背景

`models/` 同时放完整网络、残差块、编码工具、元数据工具，且 `__init__.py` 执行注册。读目录无法辨认哪些模块是可选择的网络；导入一个工具会先执行包初始化，加载整网并触发注册，形成不必要的反向依赖。

## 决策

按实际职责归位，不增加模型接口或通用框架：

| 位置 | 职责 |
|---|---|
| `nn/models/shared_resnet.py`、`dual_tower.py` | 完整网络定义，包含原始棋盘到输出的计算路径 |
| `nn/components/blocks.py` | 显式复用的残差层与分组检查 |
| `nn/components/exponent_one_hot.py` | 现有两版模型显式选用的编码工具 |
| `nn/metadata.py` | 超参读取与既有产物元数据生成，不依赖整网 |
| `nn/registry.py` | 网络名称、别名、登记检查、查找与构造 |
| `nn/model.py` | 模型生命周期：构造、加载、保存、冻结与前向辅助 |
| `nn/training.py`、`runtime/` | 训练和推理流程，传原始棋盘 |

`models/__init__.py` 与 `components/__init__.py` 仅说明包职责，不导入模块、不执行注册、不转出其他层的工具。调用方直接从职责所属模块导入；移除经定义包或生命周期模块转出注册表工具的用法。

依赖方向是流程 → 模型管理/注册 → 完整网络 → 组件和元数据工具。组件与元数据不导入整网；完整网络不导入注册、加载或训练。网络构造时的参数名称、形状、历史 ID、编码公式与既有元数据行为均不变，旧权重不需要迁移。

## 验证

在独立 Python 进程逐个导入组件、元数据和空定义包，确认没有隐式导入整网、注册表或训练器。保留两版网络的输出等价、checkpoint 往返、不同编码模型、CUDA AMP 与 torch.compile 测试，并验证受导入路径调整影响的训练、推理、发布、工作台与性能配置调用链。

WSL `Ubuntu_22_04_Cuda` 全量 Python 回归：212 项通过，无失败或跳过；覆盖真实自对弈、训练、发布、迭代与 WebUI。全项目 Ruff 检查通过，Git diff 无空白错误。测试中的 36 条警告均来自已有 Gradio 接口的弃用提示。
